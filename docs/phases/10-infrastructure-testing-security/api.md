# Quality API

All endpoints are under `/api/v1/quality`. They use the existing session cookie and require current membership in `workspaceId`. IDs are validated UUIDs for workspace, job and snapshot. Evidence object identifiers are opaque strings up to 1,024 characters. Every mutation requires JSON, the configured Origin and `x-codaryn-request: workspace`.

| Method/action                                                       | Inputs                                                                                                | Result                                                                                                                                                    |
| ------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| GET `jobs`                                                          | `workspaceId`                                                                                         | Up to 20 recent eligible analysis jobs for connected repositories.                                                                                        |
| POST `request`                                                      | `workspaceId`, `jobId`, optional `externalScans=false`                                                | 202 snapshot summary. Five requests/workspace/minute. External scans require deployment permission and owner/admin.                                       |
| GET `snapshots`                                                     | `workspaceId`, `page=1`                                                                               | 20 immutable snapshot summaries per page.                                                                                                                 |
| GET `overview`                                                      | `workspaceId`, `snapshotId`                                                                           | Status, hash, commit, resource/test/dependency/finding counts, effective-severity groups, scanner statuses, diagnostics and review capabilities.          |
| GET `resources`, `tests`, `coverage`, `dependencies`, `environment` | `workspaceId`, `snapshotId`, `page=1`, `search`                                                       | 50 typed inventory objects per page, with total and source evidence. `view` identifies the inventory type.                                                |
| GET `findings`                                                      | Same pagination/search plus optional `severity`, `state`, `tool`, `category`                          | Findings overlaid with current review and effective severity; canonical snapshot stays unchanged.                                                         |
| GET `resource`, `test`, `finding`                                   | `workspaceId`, `snapshotId`, `objectId`                                                               | Resource relationships/neighbors, test-symbol links, or finding details with matched dependency provenance and review permission. Inspectors are bounded. |
| POST `review`                                                       | `workspaceId`, `snapshotId`, `findingId`, `state`, nullable `severity`, `reason`, expected `revision` | Current review after atomic audit write. Owner/admin only; 60 reviews/workspace/minute. Start revision at zero when no review exists.                     |
| GET `audit`                                                         | `workspaceId`, `snapshotId`, `page=1`                                                                 | 50 review events per page with before/after, actor and timestamp.                                                                                         |

Search is limited to 100 characters and pages to 1–1,000. Severity: critical/high/medium/low/info/unknown. States: open/confirmed/false-positive/resolved. Reasons: needs-review/verified/not-applicable/accepted-risk/remediated. A null severity removes an override. Tool filters: builtin/semgrep/osv. Categories: secret/dangerous-code/configuration/dependency. Unknown body fields are rejected; there is no arbitrary notes field.

Failures use the existing safe API error envelope: 400 invalid input; 401 no session; 403 missing review/external permission or CSRF; 404 unavailable workspace/resource; 409 extraction not ready or review revision conflict; 429 rate limit. Worker failures are safe codes in the snapshot summary, never repository text or upstream credentials. Clients should refresh before retrying a revision conflict and wait before retrying a rate limit.
