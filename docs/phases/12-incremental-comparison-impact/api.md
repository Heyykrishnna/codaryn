# Comparison API

All endpoints use `/api/v1/comparison`, the existing authenticated session and current membership in `workspaceId`. UUIDs are validated for workspace, job, snapshot and comparison IDs. Mutations require JSON, the configured Origin and `x-codaryn-request: workspace`.

| Method/action  | Inputs                                                                    | Result                                                                                                                                                                                                   |
| -------------- | ------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| GET `jobs`     | `workspaceId`                                                             | Up to 20 eligible connected repository jobs.                                                                                                                                                             |
| POST `request` | `workspaceId`, `jobId`, optional nullable `baseId`, `verifyFull=false`    | 202 version summary; five requests/workspace/minute. Baseline must be completed and belong to the same workspace/repository.                                                                             |
| GET `versions` | `workspaceId`, `page=1`                                                   | 20 version summaries per page, including repository/job/commit identity, status, hash, count and failure code.                                                                                           |
| GET `overview` | `workspaceId`, `snapshotId`                                               | Summary, reuse/verification counters, semantic content hash, analyzer identity and diagnostic/symbol/relationship/schema counts.                                                                         |
| POST `compare` | `workspaceId`, `fromId`, `toId`                                           | Saved comparison ID/hash. Same ordered pair returns its existing result; ten new pairs/workspace/minute. Both versions must be completed and from the same repository.                                   |
| GET `history`  | `workspaceId`, `page=1`                                                   | 20 saved comparison summaries per page.                                                                                                                                                                  |
| GET `detail`   | `workspaceId`, `comparisonId`, `page=1`, `view=changes`, `kind`, `search` | Up to 50 architecture changes, schema changes or potential impact records, with total, drift signals, truncation and static semantics. Views: changes/schema/impact. Kinds: empty/added/removed/changed. |
| GET `policies` | `workspaceId`                                                             | Up to 100 repository policies and current management permission.                                                                                                                                         |
| POST `policy`  | `workspaceId`, `jobId`, `ref`, `enabled`                                  | Saved branch/template policy for the selected job's connected repository. Owner/admin only. Template manifest must validate.                                                                             |

Mutation bodies reject unknown fields. Ref values use a bounded ASCII `refs/heads/...` subset, maximum 200 characters, without `..`, `//`, trailing slash or `.lock` suffix. Pages are 1–1,000; search is at most 100 characters.

Failures: 400 malformed/unsupported input or different repositories; 401 no session; 403 CSRF or policy role denial; 404 unavailable workspace/resource/baseline; 409 version not ready; 422 comparison exceeds supported output bounds; 429 manual rate limit. Other internal failures use the existing generic safe API envelope.

The existing `/api/v1/github/webhook` endpoint validates HMAC-SHA256 over the exact raw body, GitHub event and delivery headers before processing. Push payloads require installation/repository IDs, before/after SHAs and branch ref. Matching configured pushes schedule transactionally; duplicates do not create new jobs. Queue capacity returns 503 and rolls back the receipt. Non-push webhook responses retain their previous contract. Neither scheduling nor comparison returns source text or upstream credentials.
