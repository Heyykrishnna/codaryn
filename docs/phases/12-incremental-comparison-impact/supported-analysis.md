# Supported analysis and limits

| Area                 | Implemented behavior                                                                                              | Interpretation/limits                                                                                                                                                                                                                                                          |
| -------------------- | ----------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Source versions      | JS/TS/JSX/TSX declarations and static import/export module references, content hashes and line evidence           | Syntax projection only. No cross-file type checker, inferred call graph or runtime dispatch guarantee. Dynamic imports, malformed syntax and pattern/computed names carry diagnostic codes.                                                                                    |
| Cache reuse          | Compatible unchanged local file artifacts, checksum validation, immutable baselines                               | Only version-engine artifacts are reused. Existing frontend/backend/execution/quality snapshots are not rewritten or claimed to share this cache.                                                                                                                              |
| Configuration        | Root `tsconfig.json` baseUrl/paths, repository JSON/YAML configuration hashes, validated Studio settings/registry | Nested config inheritance, project references and package exports are not expanded. Unsupported/oversized alias maps fall back to conservative unresolved/external resolution. All configuration changes invalidate compatibility.                                             |
| Input selection      | Existing archive exclusions/gitignore plus Studio exclusions, includeTests and generated-header filtering         | Existing ingestion defaults exclude dependency/build/coverage directories. Generated detection uses the first 512 source characters; it is heuristic. The projection always analyzes supported module/schema structure rather than rerunning every configured domain analyzer. |
| Schema comparison    | SQL/Prisma/Drizzle adapters from Phase 8; table/column/constraint/relation/enum fingerprints                      | Defaults and expressions are compared through hashes. Raw schema source and literal values are not exposed in this projection. Existing Phase 8 grammar limits apply.                                                                                                          |
| Graph reconciliation | Rebuild resolved module edges from current file set after every run                                               | Unsupported and external references remain separate from resolved archive targets. No third-party dependencies are installed or resolved through the host filesystem.                                                                                                          |
| Change impact        | Changed declarations and conservative transitive reverse module dependencies from old and new graphs              | Potential affected modules with traceable predecessor/depth; not exact affected-symbol execution or a proof that tests/production behavior change. Comment-only content changes may seed conservative impact.                                                                  |
| Push scheduling      | Signed push event, exact configured branch ref, installation/repository binding and SHA deduplication             | One ASCII branch policy per repository. Deleted branches are ignored. No live GitHub App configuration is silently changed. Subscribe the App to push events during deployment.                                                                                                |
| Full verification    | Same supported semantic version projection from incremental versus independent full extraction                    | A mismatch publishes full output. This does not assert equivalence of all earlier domain analyzers or runtime behavior.                                                                                                                                                        |

Manual comparisons may select any two completed versions of the same authorized repository; commits do not need to be ancestors. File renames are represented as removed/added paths. Historical versions and saved comparison results remain immutable. Analyzer changes must bump the engine version before reusing caches with changed semantics.

No external vulnerability service, LLM or source execution is introduced by this phase. Broader semantic incremental analysis, rename detection, exact symbol-level impact, additional webhook event types and production-scale performance qualification remain outside the implemented projection.
